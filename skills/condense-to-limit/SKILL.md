# 压缩到篇幅上限，把内容迁入附录

这类工作的形状是固定的：**一份已成型的长稿 + 一个硬上限 + 一个可以承载冗余的容器**。目标不是删掉观点，而是改变承载方式——正文承载论证链，附录承载证据、程序、清单、个案。读者读正文能跟上论证，想复核时能在附录找到全部原始材料。

"附录"在不同文体里名字不同：期刊论文叫 appendix / supplementary material / online supplement，研究报告叫附件，申报书叫支撑材料，书稿叫附录章。规则一样。

## 不可动摇的三项

| 项 | 允许的操作 | 不允许的操作 |
|---|---|---|
| 论点 | 合并表述、把长论证压成一句 | 删掉论点、把有条件的结论说成无条件 |
| 证据 | 搬家、合并引注、表格化 | 删数字、删引注、删掉反例 |
| 限定条件 | 集中到一处说清 | 因"占篇幅"而省略 |

压缩只改承载方式。凡删证据，原处必须留回指；凡压限定条件，那句话就变质了。

## 阶段 0　先取限额，再定口径

**限额不是常量，是这次任务的输入。** 它来自三个地方，取到哪一个就用哪一个，并在回复里写明来源：

| 来源 | 例子 | 注意 |
|---|---|---|
| 用户直接给的数字 | "压到 6,500 词""正文 15 页以内"（此处仅为举例，实际取值以用户所说为准） | 记清单位：词/字/字符/页 |
| 目标载体的规定 | 期刊投稿须知、会议模板、课程作业要求、资助方页数限制 | 规定常附连带条件：摘要 ≤ 250 词、图 ≤ 6 幅、脚注是否计入 |
| 由其他约束换算 | "排版后不超过 12 页"→ 按版式折算词数；"删掉三节"→ 折算成目标量级 | 换算要说明依据，估算即可 |

三条纪律：

1. **没有限额就不启动这个流程**——"尽量精简"不是限额；此时应先问清目标，或改做改写而非压缩。
2. **限额可能分层**：总字数之外，常有单节上限、摘要上限、附录是否计入。分层时列出每一层，别只盯总数。
3. **限额会变**：改投别的刊物、编辑回信放宽/收紧、加了一段必须写的内容——每次变化都要重记"上限 / 现状 / 余量"，不要沿用上一轮的数字。

口径同样要写清：字数含不含摘要、参考文献、表注、脚注；中文按字符还是字数；页数是 A4 还是期刊版式。同时列出结构现状（章节、附录、表、图，编号与首次引用顺序是否已一致），据此算余量——上限减现状，明确"还能加几个字"，后续任何增补都说明从哪里扣。

体例规则见 `references/style-checklist.md`（数字、日期、标点、标题、表注、引注）。

## 阶段 1　先找可迁移的候选，不改一个字

按"正文读者是否需要"排序，越靠前越该搬：

- 文献综述的逐条比较、与单一研究的对话
- 数据来源、检索策略、编码规则、抽样细节
- 访谈记录、案例全文、田野笔记
- 计算过程、代码、稳健性检验
- 程序性说明（审批流程、文件编号、机构沿革）
- 例外个案、反例、失败的尝试

判据一句话：**正文读者需要知道结论，附录读者需要复核过程。**

## 阶段 2　迁移（正文这一侧）

- 主句留论证，细节句整段搬走，不要在正文里留半截
- 搬走的位置补一句概括 + 回指：`(see Appendix B)`、`（见附件二）`
- 删句后相邻两句若失去主语或因果，补一句过渡——**压缩最容易在这里断链**，每搬完一个主题块就回读该段
- 一次只搬一个主题块，搬完立刻核字数，别攒到最后

## 阶段 3　附录这一侧

- **一个附录一个主题**；主题不相关的宁可新开一个，不要塞进相邻附录凑数
- **每个附录有导言段**：收录什么、分几节、支撑正文哪些部分；体例全篇统一
- **层次固定**：附录标题 → `X.1` → `X.1.1`；单表附录也给小节标题，避免"标题紧跟表格"的空壳
- **表必须有注**：口径、缩写、缺失值处理写在注里
- **搬进来的材料要能独立读懂**：谁、何时、依据哪份文件、结论是什么
- **不写元话语**：不出现"这段本应放在正文""因篇幅所限移入此处""以下为完整版""材料性质为二手"——读者不知道原稿有多长，这类说明只制造噪音。要交代证据强弱，就把判断放进一张证据分级表，一处说清

## 阶段 4　重编号与交叉引用

编号按首次被引用的顺序排；一旦改动，四处同步：正文、附录内部、图表、脚注。检索旧编号时连"Section 5.10"这种带小节的、以及"Table B1"这种带字母前缀的一起搜。

## 阶段 5　核验与交付

1. 重算字数，报出"当前 / 本次上限 / 余量"，并注明上限取自哪里（用户原话、刊物须知、折算）
2. 跑 `scripts/verify_condensed.py`：交叉引用是否有效、重复句、字符异常、体例偏差、表注缺失；`--limit` 传本次上限，不传则只报现状
3. 转 PDF 核页数与表数（页数/表数突然变化说明有内容被误删或重复）
4. 回读所有改动段落——长句断开后常缺主谓，括号拆开后常缺指代
5. 交付时列表说明：迁走了什么、留在正文的概括句、字数变化、编号变动清单

## 反面清单（做了等于白压缩）

- 删掉证据只留结论，读者无法复核
- 把"在 X 条件下成立"压成"成立"
- 在附录里解释为什么搬到附录
- 用"限于篇幅""鉴于资料局限不作结论"当挡箭牌——要么说清缺什么，要么直接写结论
- 正文与附录对同一事实给出不同数字（搬迁时最容易出现）
- 把某一次的限额当成通用值：上一份稿的上限，不代表这一份也是同一个数

## 与作者协作的确认门

- **开工前**：硬上限、字数口径、能否新增附录、能否改编号——这四项若不清楚，先问
- **作者原稿的重复不要擅自删**：结论重申限度、不同章节各自交代背景属于常态；只有逐字相同的整句才值得处理
- **事实冲突**（年份、人数、比例两处不一致）选有出处的那个，并在回复里点明冲突，等作者确认，不要默默统一
- **没有记载的内容不写**，但"理由未公布"本身是事实，要写
- 每轮只改约定的范围；范围一变，编号与交叉引用要整轮重核

## 交付布局

```
output/   正文、附录（可合订可单件）、表图单册、同名 PDF
work/     正文与附录的单一源文件、构建脚本、原始完整稿的逐段导出
```

单一源 + 脚本重建的价值：每轮都要重算字数与页数，手工改产物无法复现，也容易出现"改了正文忘了附录"。直接在 docx 上改也可以，但改动要回写到源或脚本，否则下一轮重建会抹掉（见 `references/docx-surgery.md`）。

## 示例

下面用 `L` 表示**用户这次给出的上限**——它可能是 6,000 词、12 页、20,000 字符，也可能是"正文砍三分之一"。技能不预设任何数值。

**示例一（期刊论文，限额按字数）**
用户："正文压到 L 词，多出来的放附录。"
做法：确认口径（L 是否含摘要与参考文献）→ 量基线，算出需减多少 → 标出可迁移块：编码规则、检索策略、个案全文、计算方法 → 整块搬入附录，正文每处留一句概括 + `(see Appendix B)` → 补过渡句 → 重算，报"当前 / L / 余量" → 重排表图编号并全篇同步 → 脚本核验 → 交付。

**示例二（中文研究报告，限额按字符，且分层）**
用户："正文压到 L 字，附件的字数不限，但摘要必须 ≤ M 字。"
做法：把"调研方法""样本构成""逐条访谈摘录""完整数据表"移入附件 1–3，正文保留方法概述与关键结论；附件各加导言段与编号层次；摘要单独按 M 收紧；正文原有回指随附件编号变动全部重核；交付时同时报正文与摘要两个数，并说明字符口径。

**示例三（限额来自载体而非用户口述）**
用户只说"要投这家刊物，超了"。做法：先取投稿须知的限额与连带条件（摘要、图数、脚注是否计入），把规定原文写进回复作为依据；若须知只给页数，按版式折算成词数并说明是估算；后续改投别家时重新取限额，不沿用旧值。
