# 附录与补充材料的设计

附录不是"删掉的垃圾场"，是**另一层阅读**：正文给论证，附录给可复核性。判据始终是同一条——读者是否需要在这里跟得上论证；需要复核过程时，是否能在附录里找到完整材料。

## 什么该进附录

| 类型 | 例子 | 为什么不在正文 |
|---|---|---|
| 材料与方法细节 | 检索式、抽样框、编码手册、问卷全文 | 正文只需交代"怎么做、为什么可信" |
| 数据与计算 | 完整表格、稳健性检验、代码、公式推导 | 复现用，不承担论证 |
| 个案与引文 | 访谈记录、档案全文、案例时间线 | 太长，正文只留提炼后的一句 |
| 程序与制度 | 审批流程、文件编号、机构沿革 | 属于背景，读者按需查阅 |
| 与他人的逐条比较 | 与 N 项研究的逐点差异 | 正文只谈"分歧在哪、为什么" |
| 例外与反例 | 未纳入的个案、失败的解释 | 正文提一句，细节在附录 |

**不该进附录的**：任何承担论证的句子、任何数字的唯一出处（若附录丢失，正文的结论就悬空）、任何"因为放不下所以搬走"却没人会去读的东西。

## 一个附录一个主题

主题不相关的材料宁可新开一个附录，也不要塞进相邻附录凑数。判断方法：给附录起标题时，如果需要用"以及其他"来收尾，说明该拆。

拆分的另一个好处是回指精确：正文写 `(see Appendix C)` 时，读者知道那里只讲一件事。

## 每个附录的开头

三件事，一到两句：

1. 本附录收录什么（材料类型、时间范围、来源）
2. 分几节，各节讲什么（`Section C.1 …; C.2 …`）
3. 支撑正文哪些部分

这三句同时解决了读者两个问题："我为什么要点开"和"我该读哪一节"。

## 层次

```
附录标题（Title Case）
  X.1 小节（sentence case）
    X.1.1 子小节（sentence case）
```

- 编号连续，不跳号；只有一张表的附录也给小节标题
- 小节标题要能独立读懂（"The charge and what it leaves" 优于 "Analysis"）
- 层次不超过三级；到第四层说明该拆分

## 表格与图

- 表题在上、图题在下；每表有 `Notes`，逐条编号
- 注里交代：计数口径、缩写、缺失值如何处理、数据截止日期
- 三线表，不加竖线；空单元格要用注说明含义
- 附录表的编号用"附录字母 + 序号"（Table C1），便于与正文表（Table 1）区分

## 常见错误

1. **元话语**：解释"这段本应在正文""因篇幅所限移入此处"。读者不关心原稿有多长。
2. **断头材料**：搬进来一段话，没有主语、没有时间、没有出处，只有作者自己看得懂。
3. **附录与正文数字不一致**：搬迁时改了一处忘了另一处。搬完必须两边各读一遍。
4. **附录变成第二篇论文**：塞进新的论证。附录只承载已存在的证据，不承担新主张。
5. **回指缺失**：正文删了证据却不指向附录，读者以为结论无据。
6. **编号漂移**：新增附录后没有重排后续字母，或正文仍引旧号。
7. **把"限定条件"搬走**：限定条件必须留在正文，它是论点的一部分。

## 中英文差异

- 英文：`Appendix A`、`(see Appendix C.2)`、`Table C1`、`Notes`。
- 中文：`附录一`、`（见附录三之二）`、`附表 3-1`、`注：`。编号体系一旦选定，全篇统一；不要中英混用（"见 Appendix 3"）。
- 中英文混排稿件：附录标题与正文标题同语言；引文用原语言，必要时附译。
